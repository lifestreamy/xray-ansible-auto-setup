# Что запланировано, что в работе, что уже сделано

Сроки примерные, не обещания. Порядок может меняться.

## Сделано в v0.4.0 (2026-09-09)

- Запуск клиента без аргументов по умолчанию разворачивает удалённый VPS (спрашивает IP и пароль);
  локальный режим — через явный `--execution local`.
- Защита от нехватки памяти на слабых VPS: при RAM < 1024 МБ и отсутствии swap клиент предлагает
  создать swap-файл 1 ГБ (явный вопрос; существующие настройки swap не трогаются).
- Полностью русский интерфейс клиента: флаг `--ru` (промпты, сообщения, ошибки, `--help`) и
  переменная окружения `XRAYVPN_LANG`; лаунчеры двойного клика на Windows — английский и русский
  (`xrayvpn-deploy.pyw` / `xrayvpn-deploy-ru.pyw`).
- Команда `xrayvpn` устанавливается в PATH: `uv tool install --editable python-client`.
- Флаги ротации в bash/PowerShell-обёртках: `--rotate`/`--no-rotate` и `-Rotate`/`-NoRotate`.
- `ufw` больше не устанавливается ролью: allow-правило добавляется только если `ufw` уже есть
  (переменная и флаг — `xray_manage_ufw` / `--manage-ufw`).
- Удалён экспериментальный рантайм `podman` (никогда не покидал experimental).
- CI: тесты клиента дополнительно на Windows и macOS; uv с фиксированной версией.
- Релизная политика: трёхзначные версии, один релиз на версию, критерии stable без календарного
  ожидания (CI-покрытие клиентских сценариев + ручная проверка по шпаргалке).

## Сделано в v0.3 (2026-09-05)

- Вся конфигурация роли (набора файлов установки Xray на сервере) — в одном файле `config/settings.yml`.
- Основной CLI-клиент `xrayvpn` (Python): удалённый режим по SSH и локальный режим; параметры —
  флагами, файлы руками править не нужно.
- CI на GitHub Actions: molecule-матрица ubuntu 22.04 / 24.04 / debian 12 плюс полный хост-прогон
  с e2e через mihomo-клиент (ufw проверяется там).
- Варианты рантайма: `native` (по умолчанию), `docker`. Контейнерные systemd-юниты
  работают в `--network host`.
- `xray.service` включается при развёртывании; `python3-venv` и `ufw` авто-устанавливались где нужно
  (поведение `ufw` изменено в v0.4.0).
- Понятные ошибки по `inventory.yml` и подсказка, как создать файл из шаблона.
- Релизная политика (`docs/RELEASE.md`), CHANGELOG (RU/EN), чистка доков под один ритм.

## Высокий приоритет

- Перевод v0.4.0 в stable — по критериям `docs/RELEASE.md`: CI-покрытие клиентских сценариев
  (python + bash + PowerShell × Ubuntu/Windows/macOS) и ручная проверка всех сценариев
  на реальном VPS по шпаргалке тестирования; без календарного ожидания.

## Средний приоритет

- **[Клиент]** — собственный визуальный клиент: кросс-платформенный, простое развёртывание
  и управление. С появлением бинарников — самореобновление по релизам (типичная схема — манифест
  `latest.json` с url и подписью на платформу) и установка из пакетных менеджеров
  (winget / choco / PyPI); имя пакета будет выбрано перед публикацией — ориентир: v0.4.1.
- **[WARP]** — продумать сценарии: несколько исходящих, вращение endpoint'а. Ориентир: нет.
